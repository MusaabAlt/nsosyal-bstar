# Protocol — m1 lexicon labels on the frozen TRAIN split (seed 42): the A-head pseudo-labels

- **Status:** written BEFORE the labels file is generated (eval/README.md "No result is committed
  before its protocol exists"). Committed in its own change; the file follows in a later commit.
- **Owner:** Musaab (m1_lexicon, project owner)
- **Date:** 2026-09-18
- **Governs:** m3 A-head training supervision (`docs/blockers/m3_head_labels.md`, owner decision
  of 2026-09-18: HYBRID strategy); m1 spec §1 (runtime signal vs frozen study slice).
- **Implementation:** `AI/eval/m1_lexicon_labels.py --split train`, run exactly as in §8.
  Output `AI/eval/derived/m1_lexicon_train_seed42.json`.
- **Sibling:** `m1_lexicon_dev_labels_protocol.md` (the dev file; same generator, `--split dev`).

## 1. Purpose — and what this file is NOT

This file records, for every row of the frozen **train** split, what `m1_lexicon` (terlik
balanced) publishes at runtime through the current `m0 → m2 → m6 → m1` path, and the A-head
pseudo-label derived from it (§5).

It exists for one use: **training supervision for m3's A head** ("profanity present", A1
carrier, ADR-005). It is a **keyword pseudo-label**, not a human label:

- it is never an evaluation oracle. Any reported A-head quality claim is measured against the
  separately human-labelled dev subset (`docs/annotation/A_HEAD_PROFANITY_GUIDELINE.md`); terlik
  agreement is reported as *agreement*, never as accuracy (owner decision 2026-09-18, item 1);
- it never defines a slice. m4's `lexicon_hit` / `lexicon_free` slice stays
  `AI/eval/frozen/study_slice_dev.json` (karaliste, dev only) and this file never touches dev rows;
- it is **regenerable**, so it lives in `AI/eval/derived/`. A change to m0, m1, m2, m6, terlik,
  zeyrek, the registry order, the pipeline or the generator means a new file, generated by the
  same command and reviewed as a data change. `python -m eval.m1_lexicon_labels --check <file>`
  reports a stale file (§7).

| frozen split | `diagnosis/data/splits/split_seed42.json` (`train_ids`; `dev_ids` read only for the disjointness check) | `73a323b9e5750faecd557470bb53e27fe26b7fdf7a1ad9da1d365f224dc6d7f2` |

The corpus is parsed as `diagnosis/src/data_io.py` parses it (id first, label last, middle

The generator opens nothing else: no path containing `testset` or `labela` is ever accepted as an
input (the official test set is SPENT and locked, `diagnosis/src/data_io.py`), and every row id
written must be an id of the training corpus.

## 3. Integrity checks (all must pass, else stop; no file is written)

1. The split's `seed` is 42; `train_ids` has 26,992 unique ids; `dev_ids` has 4,764.
2. `train_ids` and `dev_ids` are disjoint.
3. sha256 over the sorted train ids joined with `\n` equals the pinned train fingerprint
   `29a2ea8bdc9730bf7a16f6c7e21d69dd3f33648b923f2829e8e2797876bbe931` (computed once from the
   committed split file, whose sha256 is pinned above); the split's own `dev_fingerprint` equals
   `034415af3a23b388cb2bfbb13fc5eda37e43f71a3542e9ea925de72e06a133b4`.
4. Every train id is in the corpus; train gold counts are OFF 5,211 / NOT 21,781 (split
   `counts.train`).
5. m2's tier 2 (zeyrek) is available: the normalized channel is part of the label (§5), and a
   generation without zeyrek would silently label a different channel.
6. On every row: `m1_lexicon` is not degraded; `lexicon_hit`, `lexicon_hit_raw`,
   `lexicon_hit_norm` are booleans with `lexicon_hit == lexicon_hit_raw or lexicon_hit_norm`.
7. On every row: every m1 content score carries a span and a source `m1_lexicon@raw` or
   `m1_lexicon@normalized`; `text[start:end]` equals the recorded surface; a channel flag is
   true iff that channel has at least one score or the module noted a spanless match on it.
8. Determinism: the rows are generated twice in the same run; the two serialisations must be
   byte-identical.
9. Provenance: the protocol file exists and is committed; git HEAD is recorded together with the
   uncommitted changes in the watched paths (a file generated from a dirty tree says so).

## 4. How the signal is computed

Each train text goes through `pipeline.run.Pipeline` with the modules `m0_charsafe`, `m2_deobf`,
`m6_target`, `m1_lexicon`, in registry order — exactly the path the runtime signal takes (m6 is
included because m1 reads its published target for the `NON_HUMAN_TARGET` guard; the guard does
not change the hit flags). m3, m4 and m5 are not run. Values are read only from what m1
publishes; no private m1 function is called. Per-channel scores are read from `signals.decision.channel_scores`, the decision layer's pre-fusion record of every module score with its source, because the fused `content` list keeps one entry per code and span (an identical normalized channel would otherwise vanish); guards are read from `result.guards`.

**Channels.**
- `raw` = m0's charsafe text (invisible characters removed, homoglyphs mapped, Turkish I casing).
  Spans are offsets into the original text.
- `normalized` = m2's parallel channel (tier 1 + zeyrek-validated tier 2), with m2's `_offsets`
  (ADR-008) mapping every normalized-channel match back to the original text.

## 5. The A-head pseudo-label (`a_label`), owner decision 2026-09-18

```
a_label = lexicon_hit_raw
          OR (lexicon_hit_norm AND at least one normalized-channel match with a valid span)
```

- The positive signal is `lexicon_hit` (raw OR normalized), not `lexicon_hit_raw` alone
  (owner decision, item 2).
- A normalized-only hit counts as "profanity present" **only when its mapping back to the
  original text is valid**: m1 emitted a spanned `A1@normalized` score through m2's `_offsets`
  (ADR-008 §4–§5). A normalized-only hit that m1 could only report as a flag (no offset map,
  OPEN_QUESTIONS Q9) is recorded (`counts.norm_hit_unmapped`) and labelled 0. With ADR-008
  implemented on both sides this count is expected to be 0; a non-zero count is reported, never
  silently absorbed.
- Reconciliation with Q5 / ADR-008: this is the **label** half of Q5. The **runtime** half —
  whether a normalized-only hit fires a code at inference — is unchanged and stays with
  `fusion.strategy: max` over `[raw, normalized]` as configured (ADR-008 §6; OPEN_QUESTIONS Q5).
  The label rule and the runtime rule are recorded separately so neither is read as the other.
- Guards do not enter the label: a `HOMONYM` or `SUBSTRING_COLLISION` guard suppresses a *score*
  at the decision layer, while `lexicon_hit` records the *match*. Rows whose every spanned match
  is covered by a `HOMONYM` guard are counted (`counts.rows_all_matches_homonym`) so the owner can
  see how many pseudo-positives the guard would have removed; the count is reported, the rule
  above is what is applied.

## 6. Output

`AI/eval/derived/m1_lexicon_train_seed42.json`, UTF-8, LF. A header object, then `rows`, one row
per line, in `train_ids` order.

Header: `_README`, `protocol` (path, sha256, last commit or null, committed_and_unchanged),
`generator` (script, version, git HEAD, uncommitted changes in the watched paths, python),
`created_at`, `engine` (m1 `engine` signal, terlik version, zeyrek version, modules in order,
module versions, m2 tier-2 state), `inputs` (§2 with hashes), `split` (name, seed, n,
fingerprint), `channels`, `counts`, `rows_sha256`, `limits`, `row_fields`.

Row:

| field | type | meaning |
|---|---|---|
| `row_id` | str | corpus id |
| `lexicon_hit` | bool | m1 `lexicon_hit` |
| `lexicon_hit_raw` | bool | m1 `lexicon_hit_raw` |
| `lexicon_hit_norm` | bool | m1 `lexicon_hit_norm` |
| `channel` | str | `raw`, `normalized`, `both` or `none` |
| `a_label` | int | the pseudo-label of §5, 0 or 1 |
| `roots` | list[str] | m1 `matched_roots` (both channels together) |
| `matches` | list | `{channel, start, end, surface}`: each A1 score's span and the original substring |
| `collisions` | list | `{start, end, surface, evidence}`: each `SUBSTRING_COLLISION` guard |
| `homonyms` | list | `{start, end, surface, evidence}`: each `HOMONYM` guard |

## 7. Staleness

`python -m eval.m1_lexicon_labels --check <file>` recomputes what can be recomputed without the
corpus and exits 1 on any of: protocol sha256 differs from the committed protocol; generator
version differs; a module version, the terlik version or the zeyrek version differs from what
is installed; an input sha256 differs (when the input exists on the machine); `rows_sha256` does
not match the rows; the row ids are not exactly the split's ids for that split. The unit tests run
this check on every committed derived file, so a stale file fails the suite.

## 8. Limits (stated in the header and wherever numbers from this file appear)

- Gold is OFF/NOT. Any rate computed from this file measures lexicon hits against OFF, never
  "profanity present" against a human judgement.
- terlik is not karaliste (m1 spec §5); no A4 (sacred-concept) coverage.
- The label is a keyword label: an A head trained on it learns terlik's coverage, and its
  quality is only known against the human-labelled dev subset.

## 9. Command

Run from `AI/` with `AI/.venv` (terlik and zeyrek installed):

```bash
python -m eval.m1_lexicon_labels --split train --out eval/derived/m1_lexicon_train_seed42.json
```

The file is committed only after this protocol is committed, in a separate, later commit.

## Amendment 2026-09-18 — pseudo-label rule **v2** (aligned with annotation guideline v1.1)

**Status:** pre-registered. Committed BEFORE any v2 label is generated or counted. Supersedes §5
(rule v1) for every file generated from generator version 3.0.0 on. Applies identically to the
dev file (diagnostic / agreement reporting only).

### Why v1 is superseded

Rule v1 labelled a post positive on **any** terlik match. terlik's Turkish dictionary is broader
than the A head's concept: of its 147 roots only 18 are category `sexual`; 104 are category
`insult` (`aptal`, `salak`, `eşek`, `rezil` …). Annotation guideline v1.1 (owner decision
2026-09-18) defines the A head as **explicit profanity — an obscene or profane root present** and
scores ordinary insults `0`. The first GPU candidate (`m3-berturk-multihead-2026-09-18`, trained
on v1 labels) is therefore recorded as TECHNICALLY_VALID_BUT_A_SEMANTICALLY_MISALIGNED
(`docs/training/runs/m3-berturk-multihead-2026-09-18.md`). A threshold cannot repair a
target-definition mismatch; the supervision must change.

### Source of the rule — and what it was NOT derived from

The rule is a function of two committed, pre-existing sources only:

1. **terlik 0.1.0's own metadata**: every root of `terlik/lang/tr/dictionary.json`
   (sha256 `e83a97b38c553227cd20c2b5688939fda6037fb30b4964e9fd063a125a9a641c`) carries a
   `category` (`sexual` / `insult` / `slur` / `general`) and a `severity` (`high` / `medium` / `low`).
2. **The sealed guideline text** (v1.1, sha256 `72e61d19…`), which names specific roots as profane
   or as not profane. Every root it names as profane was already named in v1.0, committed at
   `2072497`, before any annotation or evaluation existed.

It was **not** derived from the 500-row AI-assisted, human-adjudicated dev reference, from any
individual candidate error, or from the test set. The classes below are whole metadata classes;
no root was moved between classes because of how a dev row was labelled or scored. (Disclosure: the
session that wrote this rule had seen the candidate's dev false positives. That is exactly why the
rule is restricted to class-level metadata plus pre-existing guideline text: anyone can re-derive
it from those two sources without access to the reference.)

### The classes

| class | definition | roots | basis |
|---|---|---|---|
| **POSITIVE** | `category == "sexual"` (all 18) | sik, amk, yarrak, göt, am, döl, hassiktir, sktrgt, kerhane, fuhuş, aşifte, kaşar, kancık, sakso, sg, taşak, meme, amcı | guideline §1: "an obscene sexual … term"; terlik's own class of obscene sexual roots |
| **POSITIVE** | roots the sealed guideline itself names as profane (3) | `bok` (§3 non-human row, §9), `piç` (§3 collision row: "`piç` in `kerpiç`"), `oç` (§2 abbreviations) | guideline text, present since v1.0 |
| **EXCLUDED** | `category == "insult"`, severity `low` (34) or `medium` (61) | aptal, salak, gerizekalı, mal … / rezil, kalleş, şerefsiz, eşek, maymun … | owner decision v1.1: ordinary insults are `0`; its named examples lie in exactly these classes (`aptal`, `salak` ∈ insult/low; `eşek` ∈ insult/medium); the guideline names no root of these classes as profane |
| **EXCLUDED** | `category == "general"`, severity `high` (20) | geber, boğazınıkeserim, canınıalırım … (threats); allahbelanıversin (sacred); defol, kaybol, çüş … (dismissals) | guideline §3: threats are B2, sacred-concept content is an A4 candidate and `0`; neither is lexical profanity |

### Rule v2

Let *valid hit* be rule v1's condition (§5): a raw hit, or a normalized hit that m1 mapped back to
the original text. Let *R* be m1's `matched_roots` for the post.

```
a_label = 1     if valid hit AND R ∩ POSITIVE ≠ ∅
a_label = null  if valid hit AND R ∩ POSITIVE = ∅ AND R ∩ REVIEW ≠ ∅     (masked: no supervision)
a_label = 0     otherwise  (no hit, or only EXCLUDED roots)
```

- **Masking, not guessing.** A post whose only matches are REVIEW roots gets no A label at all:
  the trainer masks the A loss on it (`MISSING`), so the undecided class supervises nothing in
  either direction. When the owner decides, the rule becomes v3 and the files are regenerated.
- **Channels:** unchanged from v1 — raw OR normalized-with-valid-span (the label half of Q5).
- **Guards:** unchanged — recorded, never applied to the label. m1 0.1.1's `amin` whole-word
  rule turns that match into a collision upstream, so it never reaches `matched_roots`.
- **Limit (stated):** `matched_roots` is per post, not per span; a root matched only on a channel
  without a valid span could enter *R*. `counts.norm_hit_unmapped` must be 0 for the file to be
  used, which makes the two readings coincide.
- **Row fields added:** `a_label_v1` (the v1 value, for the old/new comparison only) and
  `root_classes` (`{"positive": […], "excluded": […], "review": […]}`). Header: rule version 2,
  the dictionary sha256, `counts.a_label_null` and per-class row counts.
- **Determinism, provenance, train/dev/test separation:** exactly as §2–§3 and §7 (two
  byte-identical passes, git HEAD and dirty state, input digests, test-set paths refused, ids ⊂
  training corpus). The generator additionally stops if the installed terlik dictionary's sha256
  is not the pinned one, or if a matched root belongs to no class.
- **The 500-row dev reference** (`eval/annotation/private/a_dev_ai_assisted_adjudicated.jsonl`)
  is an EVALUATION set only: never read by the generator (pinned by a test), never a training
  label, never a source of rule edits.

## Amendment 2026-09-18 (b) — pseudo-label rule **v3**: the frozen A-head lexical taxonomy

**Status:** pre-registered. Committed BEFORE any v3 label is generated or counted. Supersedes rule
v2 for every file generated from generator version 4.0.0 on, on train and dev alike (the dev file
stays diagnostic, agreement only). Rule v2 was an intermediate taxonomy experiment: its classes came
from terlik's `category` / `severity` metadata, which admitted sexual-topic vocabulary as
profanity and left 11 roots masked for review.

### Definition (owner, 2026-09-18)

**A = an explicit obscene / profane lexical root is present and used by the author.** A is NOT:

- an ordinary insult;
- derogatory language;
- an identity slur merely because it is offensive;
- sexual-topic vocabulary;
- a gendered insult merely because it is vulgar.

### Source of the taxonomy, and what it was NOT derived from

Every one of the 147 roots of the pinned terlik 0.1.0 Turkish dictionary (sha256
`e83a97b38c553227cd20c2b5688939fda6037fb30b4964e9fd063a125a9a641c`) is classified by the definition above,
annotation guideline v1.1's text, and the owner decisions below. terlik's `category` was the
starting point of the taxonomy review; it is no longer the rule. **The rule is the explicit list.**

The taxonomy was NOT derived from the 500-row AI-assisted, human-adjudicated dev reference, from
any candidate prediction or error, or from the test set. The review that proposed it read only the
dictionary entries and the guideline; the owner decided the four boundary roots and confirmed the
rest. Disclosure: `kaşar` occurs in one reference row that the owner adjudicated `0`, a fact known
before the review. Its exclusion follows from the definition (literal meaning a cheese; slang sense
a gendered insult, "promiscuous"), applied to the whole gendered-insult class alike (`aşifte`,
`fahişe`, `kahpe`, `sürtük`, `kaltak`, `kancık`, `kevaşe`). Whoever evaluates the next candidate
should note that one row.

### Rule v3

Let *valid hit* and *R* (m1's `matched_roots` for the post) be as in §5 and rule v2.

```
a_label = 1   if valid hit AND R ∩ POSITIVE_ROOTS ≠ ∅
a_label = 0   otherwise
```

The REVIEW class is **empty** in v3, so no row is `null`. The masking mechanism (`null` for a post
whose only matches are REVIEW roots) is kept in the code for a future version.
