# Protocol — m1 lexicon labels on the frozen dev split (seed 42)

- **Status:** written BEFORE the labels file was generated (eval/README.md, decision #23).
- **Owner:** Musaab (m1_lexicon)
- **Date:** 2026-09-16
- **Governs:** m1 spec §1 (runtime signal vs frozen study slice), m1 spec §6 (lexicon-signal
  metrics), owner decisions of 2026-09-16 (location, purpose, channel labelling).
- **Implementation:** `AI/eval/m1_lexicon_dev_labels.py`, run exactly as in §7.
  Output `AI/eval/derived/m1_lexicon_dev_seed42.json`.

## 1. Purpose — and what this file is NOT

This file records, for every row of the frozen dev split, what `m1_lexicon` (terlik
balanced) publishes at runtime: whether the lexicon matched, on which channel, which
roots, at which spans, and which substring collisions it rejected.

It exists for two uses only:

1. **Training labels for m3's A head** (Abdullah): a per-row lexicon signal.
2. **Comparison against the frozen study slice** (`AI/eval/frozen/study_slice_dev.json`)
   and the lexicon-signal metrics of m1 spec §6.

It is **NOT the evaluation slice.** m4's `lexicon_hit` / `lexicon_free` slice is, and
stays, `AI/eval/frozen/study_slice_dev.json`, produced once by the study's karaliste
matcher. Every published m4 number (0.5628, +0.3301, the 0.5180 → 0.6367 repair) was
measured against that file. Replacing it with this one would silently change what those
numbers mean. The two files are never merged, and neither is derived from the other.

This file is **regenerable**, which is why it lives in `AI/eval/derived/` and not in
`AI/eval/frozen/`. A change to m0, m1, terlik or the pipeline order means a new file,
generated by the same command, reviewed as a data change.

## 3. Integrity checks (all must pass, else stop; no file is written)

1. The split's `seed` is 42 and `dev_ids` has 4,764 unique ids.
2. sha256 over the sorted dev ids, joined with `\n`, equals the split's `dev_fingerprint`
   `034415af3a23b388cb2bfbb13fc5eda37e43f71a3542e9ea925de72e06a133b4` (study `dev_fingerprint`).
3. Every dev id is in the corpus; dev gold counts are OFF 920 / NOT 3,844 (split `counts.dev`).
4. The frozen study slice lists exactly the same 4,764 row ids, with the same fingerprint.
5. On every row: `m1_lexicon` is not degraded, and `lexicon_hit`, `lexicon_hit_raw`,
   `lexicon_hit_norm` are booleans with `lexicon_hit == lexicon_hit_raw or lexicon_hit_norm`.
6. On every row: every m1 content score carries a span and a source `m1_lexicon@raw` or
   `m1_lexicon@normalized`; a channel flag is true iff that channel has at least one score
   or the module noted a spanless match on it.
7. Determinism: the rows are generated twice in the same run; the two serialisations
   must be byte-identical.

## 4. How the signal is computed

Each dev text goes through `pipeline.run.Pipeline` with the modules `m0_charsafe`,
`m2_deobf`, `m6_target`, `m1_lexicon`, in registry order — exactly the path the runtime
signal takes. m3, m4 and m5 are not run. Values are read only from what m1 publishes
(`result.signals["m1_lexicon"]`, m1's content scores and guards); no private m1 function
is called.

**Channels, labelled honestly.**
- `raw` = m0's charsafe text (invisible characters removed, homoglyphs mapped, Turkish I
  casing), not the untouched original. Spans are offsets into the original text.
- `normalized` = m2's parallel channel. **While m2 is a stub it publishes no normalized
  text, so m1 does not scan this channel at all: `lexicon_hit_norm` is false on every row
  by absence, not by measurement.** The header records this as
  `channels.normalized.available = false`. No metric may be reported for it.

## 5. Output

`AI/eval/derived/m1_lexicon_dev_seed42.json`, UTF-8, LF. A header object, then `rows`,
one row per line, in `dev_ids` order.

Header: `_README`, `protocol` (path, sha256, last commit or null), `created_at`,
`generator` (script, git HEAD, whether m0/m1/m2/m6 or the script have uncommitted changes),
`engine` (m1 `engine` signal, terlik version, module versions), `inputs` (§2 with hashes),
`split` (seed, dev fingerprint), `channels` (§4), `counts`, `rows_sha256`
(sha256 of the serialised rows block), `limits`.

Row:

| field | type | meaning |
|---|---|---|
| `row_id` | str | corpus id |
| `lexicon_hit` | bool | m1 `lexicon_hit` |
| `lexicon_hit_raw` | bool | m1 `lexicon_hit_raw` |
| `lexicon_hit_norm` | bool | m1 `lexicon_hit_norm` (always false while m2 is a stub, §4) |
| `channel` | str | `raw`, `normalized`, `both` or `none` |
| `roots` | list[str] | m1 `matched_roots` (terlik roots, both channels together; m1 does not publish a root per span) |
| `matches` | list | `{channel, start, end, surface}`: each A1 score's span and the original substring |
| `collisions` | list | `{start, end, surface, evidence}`: each `SUBSTRING_COLLISION` guard |

## 6. Limits (stated in the header and wherever numbers from this file appear)

- The corpus has binary OFF/NOT gold only. Any recall, precision or FPR computed from this
  file measures **lexicon hits against OFF**, never per content code (no A-code gold exists).
- terlik is not karaliste. A difference against the frozen study slice is a **word-list
  difference** on the same population; a difference against the study's 36.5% / 63.5%
  (karaliste, full corpus, 6,131 OFF rows) mixes a word-list difference with a
  **population difference** (dev 920 OFF rows vs full corpus). The two are reported apart.
- m1 has no A4 (sacred-concept) coverage and no HOMONYM guard yet (m1 spec §4.3, §8).

## 7. Command

Run from `AI/`, with `modules/m1_lexicon/requirements.txt` installed:

```bash
python -m eval.m1_lexicon_dev_labels --out eval/derived/m1_lexicon_dev_seed42.json
```

The file is committed only after this protocol is committed, in a separate, later commit.

## Amendment 2026-09-18 (owner decisions of 2026-09-18; regeneration on the implemented m2 / m6)

The file described above was first generated on 2026-09-17 with `m2_deobf` and `m6_target` as
stubs (header `module_versions` 0.0.0). Both are now implemented, m1 gained the `HOMONYM` guard
and the span-tightening rule, and the owner has decided the A-head strategy. The following
supersede the paragraphs they name; everything else stands.

1. **Generator.** `AI/eval/m1_lexicon_labels.py --split dev` (shared with the train protocol,
   `m1_lexicon_train_labels_protocol.md`). `eval/m1_lexicon_dev_labels.py` is a thin entry point
   that calls it with `--split dev`; §7's command still works. Generator version is recorded in
   the header.
2. **§4 Channels.** The normalized channel is now available: m2 publishes `normalized_text` and
   `_offsets` (ADR-008), m1 scans it and maps every match to the original text. The header
   records `channels.normalized.available = true` and the zeyrek version; generation stops if
   zeyrek (m2 tier 2) is unavailable, exactly as the train protocol §3.5 requires.
3. **§5 Row.** Two fields are added: `a_label` (the A-head pseudo-label, rule in the train
   protocol §5 — applied identically here so the dev file can report *pseudo-label agreement*, never
   accuracy) and `homonyms` (each `HOMONYM` guard, `{start, end, surface, evidence}`). Header
   `counts` gains `a_label`, the channel breakdown (`raw_only`, `normalized_only`, `both`),
   `norm_hit_unmapped` and `rows_all_matches_homonym`.
4. **§1 Purposes.** Purpose 1 is narrowed: on dev this file provides *pseudo-label agreement*
   for the A head, never its evaluation. The A head's evaluation oracle is the human-labelled dev
   subset (`docs/annotation/A_HEAD_PROFANITY_GUIDELINE.md`). Purpose 2 (comparison against the
   frozen slice) is unchanged.
5. **§3 Integrity.** Check 6 additionally requires `text[start:end]` to equal the recorded
   surface for every match, collision and homonym; a provenance check (protocol committed, git
   HEAD and dirty state recorded) is added; `--check` staleness detection as in the train protocol §7.
6. **§4 Reading the scores.** Per-channel scores are read from `signals.decision.channel_scores`
   (pre-fusion, one entry per source) rather than the fused `content` list, which keeps one entry
   per code and span and would hide an identical normalized channel (train protocol §4).
