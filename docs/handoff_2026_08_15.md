## 2. The committed framing — read this before drafting anything

The report's central claim was reframed by the project lead and this framing is
**settled**, not open:

> The contribution is **reducing lexical dependence.** The primary endpoint is
> therefore **`lexicon_free` OFF-recall**, not macro-F1. The report presents the
> ~3.5pp gain as a **measured improvement**, and reports macro-F1 staying flat
> and the `lexicon_hit` cost **openly, in the same tables and the same section**
> — as stated costs, not as a verdict that the work failed.

What makes this legitimate rather than convenient, and what must appear wherever
the endpoint is declared: **`lexicon_free` recall was the pre-registered target
of the intervention, fixed before any defense number existed.**
`phases/03_defense_design.md` records *"Targets. 1a → the lexicon-free false
negatives"*, and the same document pre-registers the "within-gap trade" failure
mode with the requirement that all four metrics be reported together. Choosing
the favourable metric afterwards would be invalid; measuring against a target
declared in advance is a contribution claim. The difference is the timestamp, and
the report must cite it. This argument is already written into `report/01…§1.7`.

**Two registers, deliberately different, both correct:**

* `results/03_defense/findings.md` says **"the component works, the system does
  not."** That is the internal record and it **stays as written.**
* The report frames the same numbers as a measured improvement with stated costs.

These are not in conflict — same evidence, different document purpose. Do not
"harmonise" them by softening findings.md or by hardening the report.

Three facts about these that are easy to get wrong:

1. **The gap replicates and is larger on test, but the widening is not itself an
   established difference** — the dev and test intervals overlap over
   [+0,3418, +0,3827]. Both statements must appear together. The mechanism is
   recorded: `lexicon_hit` +1,4pp, `lexicon_free` −5,3pp from dev to test.
2. **The `lexicon_free` gain is the only defense effect that excludes zero on
   test.** On dev the `lexicon_hit` loss also excluded zero; on test it does not.
   That difference is the substance of the Phase 3 correction row in the log.
3. **Calibration:** raw needs none (T = 0,9948; ECE 0,0205 → 0,0191). The defense
   variant is badly miscalibrated (T = 1,9732; ECE 0,0786 → 0,0270).

**Selective prediction, on the official test set, at thresholds frozen in Phase 4
and never re-derived:**

> %90,2 kapsam → 0,8485 macro-F1 / %8,52 hata, %9,8 devir; hata yoğunlaşması 3,59×
> %79,8 kapsam → 0,8900 macro-F1 / %5,43 hata, %20,2 devir; 3,15×

And the finding that must not be overstated: **deferral is error-selective but
slice-blind** — `lexicon_free` deferred at 9,8% against `lexicon_hit` at 10,0%.
It does not preferentially route the lexicon-free failures to humans. This
replicated from dev to test and is reported as a null.

## 5. Binding rules that survive this chat change

These outrank convenience and they are not negotiable by a fresh session:

1. **The official test set is spent and guarded.** `results/05_final_test/TEST_SET_SPENT.json`
   exists and `src.data_io.load_coltekin_test` refuses while it does, on any
   clone. Deleting it is a project-lead decision that must be recorded in
   `docs/RESULTS_LOG.md`. The set was opened twice; both opens are logged and the
   first produced no numbers. **Report that, do not tidy it away.**
2. **The lexicon is frozen.** Never modify `karaliste.txt`. The slice matcher is
   `lexicon.hit_root` — import it, never reimplement it.
3. **Dev-derived signals never re-enter training.** This is the rule that Phase 3
   violated once and had corrected; see `phases/03_defense_design.md` C1.
4. **`docs/RESULTS_LOG.md` is append-only.** A later result that contradicts an
   earlier one gets a **new correction row**; the old row is never edited. Two
   correction rows exist already.
5. **Every number traces to a recorded run.** If a figure is not in the record,
   flag it — do not write it, and do not reconstruct it from memory or from this
   brief.
6. **Deltas are reported with CIs regardless of sign**, and per-slice macro-F1 is
   never reported (base rates differ; the constraint is pre-registered in
   `phases/01_baseline_diagnosis.md`).
7. **The repository stays private** — `src/obfuscation.py` generates functional
   evasion text.

## 8. Working practices worth knowing

* **Colab is driven through an MCP proxy.** Verify which notebook is attached
  before pasting — a restored browser tab has reconnected to a stale runtime
  before. Check the device name and look for leftover cells.
* **`notebooks/colab_phase01_runbook.md` §1 is a one-paste session rebuild** with
  seven verified gates. Use it; do not reconstruct setup by hand.
* **Colab secrets are per-notebook.** A rebuilt notebook needs `GH_TOKEN`
  notebook-access re-granted, and Drive's OAuth popup must be clicked inside
  120 s or the mount raises.
* **`git pull` in the Colab clone collides** with run outputs that were untracked
  locally and are now tracked upstream. The safe sequence: hash the local files,
  back them up, remove, pull, re-hash, confirm identical.
* **Moving result files off Colab:** gzip + base64 through a notebook cell, then
  decode locally and compare sha256. Verified byte-identical in both directions.
* The GPU has been an **L4**, not the T4 sometimes assumed. `run_config.json`
  records what actually ran.
